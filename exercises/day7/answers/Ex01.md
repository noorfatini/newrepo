# Day 7 Exercise 1: Install and Secure MongoDB - Answers

## Setup
- Installed MongoDB Community Server, MongoDB Compass, and `mongosh`.
- Enabled `authorization: enabled` in `mongod.cfg` and restarted the `MongoDB` Windows service.
- Created a `root` administrator in the `admin` database, then created a scoped application user (`support_desk_app`) with `readWrite` on `support_desk_db` only.

---

## Reflection Questions

**1. What is the purpose of the `admin` database?**
It's MongoDB's special database for cluster-wide administration — it stores user accounts, roles, and privileges, and is where you must authenticate to run admin-level commands (e.g. creating users, managing other databases).

**2. Why should an application use its own database user instead of the root administrator?**
Least privilege — the app user only gets `readWrite` on its own database, so if its credentials leak, the damage is limited to that one database instead of the whole server.

**3. What is the difference between authentication and authorization?**
Authentication verifies *who* you are (login with username/password). Authorization determines *what* you're allowed to do once logged in (e.g. read-only vs read-write, which databases).

**4. What would happen if authentication was disabled on a production database?**
Anyone with network access to the server could connect with no credentials and freely read, modify, or delete all data — a major security risk (data theft, ransomware, accidental data loss).
