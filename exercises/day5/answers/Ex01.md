## Response Type Guide (for reference)
- List — an array `[ ... ]` of multiple items
- Single object — one item `{ ... }`
- Error object — `{ message: ..., errors: [...] }` describing what went wrong
- Empty response — no body returned

## Questions to Answer

**1. Which request returned a successful list response?**
`GET /api/course-offerings` returned a successful list response (status 200) — it gave back an array of all course offerings.

**2. Which request returned a not-found response?**
`GET /api/course-offerings/C999` returned a not-found response (status 404), because that id does not exist in the data.

**3. Which request returned a validation error?**
`POST /api/course-offerings` with empty title, empty instructor, empty date, and capacity 0 returned a validation error (status 400), because the required fields were missing or invalid.

**4. What is the difference between a successful response and an error response?**
A successful response means the server understood the request and could do what was asked — it usually comes with a 2xx status code (like 200 or 201) and returns the actual data (a list, an object, or the newly created item). An error response means something went wrong, either because of what I sent (like invalid or missing data, or asking for something that doesn't exist) or a problem on the server side. Error responses come with a 4xx or 5xx status code, and instead of real data, the body just explains what went wrong (a `message`, sometimes with a list of `errors`).

**5. Why is the status code important for frontend developers?**
The status code tells the frontend, at a glance, whether a request worked or not, without needing to guess by reading the whole response body. For example, frontend code can check "if status is 200 or 201, show the data" or "if status is 404, show a 'not found' message" or "if status is 400, show the validation errors next to the form fields". This makes it possible to write proper error handling and give useful feedback to the user, instead of the app just breaking silently or crashing when something unexpected happens.
